# AetherAC Governance

## Project Structure

AetherAC is an anti-cheat project with the following structure:

### Core Team

The Core Team consists of project maintainers who have:

- Demonstrated commitment to the project
- Shown technical expertise in anti-cheat development
- Proven ability to work constructively with the community

Core Team responsibilities include:

- Reviewing and merging pull requests
- Setting project direction and priorities
- Managing releases
- Moderating community discussions

### Project Lead

The Project Lead (`Aether-254`) has final decision-making authority on:

- Major architectural changes
- License and legal matters
- Project branding and naming
- Security vulnerability responses

### Contributors

Anyone who submits code, documentation, or other contributions that are merged
into the project is recognized as a contributor. Contributors are listed in the
README and release notes.

## Decision-Making Process

### Consensus

Most decisions are made by consensus among the Core Team. Consensus means that
the Core Team agrees on a course of action without any formal voting.

### Voting

When consensus cannot be reached, decisions are made by a simple majority vote
of the Core Team. In the event of a tie, the Project Lead casts the deciding
vote.

## Roles

### Maintainer

- Has write access to repositories
- Reviews and merges pull requests
- Participates in project discussions

### Core Team Member

- Has triage access to repositories
- Can label and manage issues
- Participates in decision-making

### Contributor

- Has submitted accepted contributions
- Can participate in discussions
- May be nominated for Core Team membership

## Becoming a Core Team Member

Core Team membership is granted by invitation from the existing Core Team.
Nominees should have:

- Made significant contributions to the project
- Demonstrated good judgment and community stewardship
- Been active in the project for at least 3 months

## Code of Conduct

All community members, including Core Team members, are subject to our
[Code of Conduct](CODE_OF_CONDUCT.md). Violations will be handled by the
Project Lead.
